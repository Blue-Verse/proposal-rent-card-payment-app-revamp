핵심 요구사항 분석

  • 레거시 소스코드 정밀 분석 — 폐업사로부터 수령한 프론트·백엔드 전체 소스의 언어·프레임워크 확정, 치명적 결함 및 구조적 문제점 식별, DB 스키마 분석 및 연동 상태 점검
  • PG 결제 오류 전면 정상화 — 현재 발생 중인 결제 불가 오류의 근본 원인 파악, 결제 실패·승인 지연·중복 결제 방지를 위한 검증 로직 재설계, 신용카드/할부/한도 초과 등 예외 시나리오 테스트
  • 금융 사고 방지용 본인 인증 신규 구축 — 통신사 본인인증 또는 범용 간편 인증 연동, 신규 가입 프로세스 내 인증 강제 삽입, 기존 회원 소급 적용, 인증 결과의 암호화 저장 및 회원 DB 매핑
  • 통합 운영 관리자 페이지 신규 구축 — PC 웹 기반 어드민, 전체 회원·본인인증 여부 조회, 결제/승인/취소/환불 내역 실시간 조회, 관리자 수동 강제 취소 권한
  • 양대 마켓 재출시 대응 — 금융결제 카테고리 심사 가이드라인 최적화, 클라이언트 명의 신규 개발자 계정 등록 대행, 심사 반려 시 즉각 대응

제안 포인트

1. 중단된 서비스 인수·정상화 경험. P2P 크라우드펀딩 플랫폼의 UI/UX 리뉴얼 및 운영 자동화, Connectin·EZ-Approve 등 기존 코드베이스 이관·고도화 경험을 바탕으로, 폐업사 레거시 코드를 빠르게 파악하고 무엇을 살리고 무엇을 재작성할지 명확히 판단합니다. 인수 첫 단계에서 정밀 분석 보고서와 에러 수정 계획서를 산출하여, 본 개발 착수 전 수정 범위를 클라이언트와 합의합니다.

2. 결제·본인인증 상용화 경험. NICE 본인인증(CheckPlus/SafeKey/NPAC), PG 결제대행 및 가상계좌 자동화, KYC 규제 대응을 실제 금융 서비스에 적용한 경험이 있습니다. 결제 실패·중복·승인 지연 등 결제 도메인 특유의 예외 처리와 검증 로직 재설계 노하우를 그대로 적용합니다.

3. 웹 관리자(어드민) 신규 구축 역량. EZ-Approve 전자결재 SaaS, Series-B 펀드 관리 플랫폼에서 회원·내역 실시간 조회, 권한 기반 관리자 조치(강제 취소 등), 대시보드를 다수 구축했습니다. 운영자가 결제 오류를 직접 확인·조치할 수 있는 실무형 어드민을 설계합니다.

4. 크로스플랫폼 앱 + 마켓 출시 경험. React Native 기반 앱을 Android/iOS/Web 3개 플랫폼에 동시 출시한 경험을 보유하여, 앱 마켓 심사 가이드라인 대응과 재출시 절차를 안정적으로 수행합니다.

5. 운영 자립 지원. 산출물로 관리자 페이지 이용 매뉴얼과 원본 소스코드 일체, API 명세·DB 스키마 문서를 제공하여, 본 프로젝트 이후 클라이언트가 직접 서비스를 운영하고 월 단위 유지보수·고도화를 이어갈 수 있도록 합니다.

PRD (Product Requirements Document)

프로젝트 요구사항을 정의하고 기능 범위를 명확히 합니다.

1. 프로젝트 배경 및 목적

본 서비스는 임차인이 월세를 신용카드 또는 할부로 결제할 수 있도록 지원하는 모바일 어플리케이션입니다. 초기 개발사가 폐업하면서 개발자 계정이 만료되어 현재 스토어 다운로드가 불가능하며, 결제 모듈에 심각한 오류가 발생하고 있습니다. 또한 금융 사고·분실 카드 도용 방지를 위한 본인 인증과 서비스 운영을 위한 관리자 페이지가 부재한 상태입니다.

본 프로젝트의 목적은 ① 인수한 소스코드를 정밀 분석하여 언어·프레임워크를 확정하고, ② 무너진 결제 로직을 정상화하며, ③ 본인 인증 도입과 관리자 페이지 신규 개발을 통해 안정적인 플랫폼 서비스를 양대 마켓에 재오픈하는 것입니다.

총괄 관리자서비스 운영·모니터링 담당자회원·인증 조회, 결제 내역 모니터링, 강제 취소 조치

3. 기능 요구사항

3.1 레거시 소스코드 분석 및 환경 세팅

  • [필수] 프론트·백엔드 소스의 언어·프레임워크 확정 (Java/Spring Boot 확인, 크로스플랫폼 프레임워크 식별)
  • [필수] 치명적 결함·구조적 문제점 파악 후 최종 수정 범위 획정
  • [필수] 기존 DB 스키마 분석 및 백엔드 로직 연동 상태 점검

3.2 본인 인증 시스템 (신규)

  • [필수] 통신사 본인인증 또는 범용 간편 인증 API 연동 및 예외 상황 테스트
  • [필수] 신규 가입 프로세스 내 본인 인증 강제 삽입 및 이탈 방지 처리
  • [필수] 기존 가입 회원 대상 본인 인증 소급 적용 로직
  • [필수] 본인 인증 결과 데이터의 암호화 저장 및 회원 DB 매핑

3.3 월세 카드 결제 보완 (PG 오류 수정)

  • [필수] 기존 PG사 연동 소스 디버깅, 결제 불가 오류 원인 파악·수정
  • [필수] 결제 실패·승인 지연·중복 결제 방지를 위한 검증 로직 재설계
  • [필수] 신용카드/할부 결제, 한도 초과 등 예외 상황 정상 작동 테스트

  • [필수] 결제 발생·승인 상태·취소·환불 내역 실시간 리스트 조회
  • [필수] 결제 오류 시 관리자 수동 확인 및 강제 취소 권한

3.5 양대 마켓 재출시 대응

  • [필수] 금융결제 카테고리 심사 가이드라인에 맞춘 코드 최적화

  • [필수] 심사 반려 시 사유 분석 보고 및 재요청 처리

5. 기술 제약사항

클라이언트가 보유한 소스코드는 백엔드 Java/Spring Boot(확실), 크로스플랫폼 프론트는 React Native(추정)로 파악되며, 정확한 프레임워크는 인수 직후 1단계 분석에서 확정합니다. 기존 PG사 연동과 DB 스키마를 최대한 보존·재활용하되, 결제 정합성·보안에 영향을 주는 구조적 결함은 재설계합니다. 본인인증·PG·앱 마켓 등 외부 서비스의 정책·심사 일정은 당사 통제 범위 밖이므로, 해당 의존 구간은 일정 리스크로 사전 고지합니다.

  • 신규 비즈니스 기능 추가 개발 (본 과업은 정상화·필수기능 구축에 한정)
